# 官方网页桥接：阶段记录

## 5.29 更新

用户报告第一阶段网页组件测试正常。已新增 Java 8 游戏内桥接与 Apple Music 账号入口，复用播放栏、快捷键、灵动岛和卡片的基础控制及状态。协议/游戏状态自动检查和构建通过，GTNH 实机效果待验证。详见 [游戏安装与边界](../tools/apple-web-bridge/GAME_SETUP.md)。搜索、媒体库、歌词、独立队列和 Apple 多人同步仍未接入。

## 第一阶段原始设计

基线：`0.1.0-dev.5.28`，GTNH 2.9.0 / Forge 1.7.10。用户已确认官方网页可以播放；自动电脑操作无法确认 Chrome URL，因此真实网页控制改由用户验证。

## 设计与范围

使用 Chrome/Edge Manifest V3 扩展，在用户主动选定的 `https://music.apple.com/` 标签页执行固定的播放器适配函数。本机 Node.js 原型仅监听随机端口的 `127.0.0.1`。一次性配对码换取内存会话；不读取 Cookie、Apple 用户令牌或开发者令牌。扩展只读取并返回白名单内的歌曲信息。网页现有 MusicKit 实例的可用性属于待验证能力，未找到实例时明确报告不支持，不自行创建实例或获取站点凭据。

本阶段不修改 Mod 播放器，不发布新的 Mod 版本。先交付可运行控制台原型和扩展，验证真实网页，再实现 Java 8 后端与游戏 UI；不将协议模拟测试当作完整播放验证。

| 功能 | 当前状态 | 验收 |
|---|---|---|
| 官方网页登录与播放 | 用户确认可播放；桥接尚未实测 | 超过试听时长，跳到后段仍可播放 |
| 一次性配对、来源隔离、停止屏障 | 自动测试 | 无凭据/错误来源拒绝，旧状态不能恢复停止状态 |
| 歌名、歌手、封面、时长、实际进度 | 适配器已实现，真实网页待验证 | 与网页逐项核对，暂停/手动跳转也同步 |
| 播放、暂停、停止、切歌、跳转、音量 | 固定命令已实现，真实网页待验证 | 各控制生效且无双播 |
| 标签页刷新、组件断开 | 重配对和心跳停止已实现，真实后台行为待验证 | 刷新后重连；断开最多约 10 秒尝试暂停 |
| 搜索、媒体库、收藏、推荐 | 待验证，未接入 | 独立评估站点可用能力，不抓取令牌 |
| 游戏队列、HUD、快捷键、两套歌词 | 待接入 | 最小闭环通过后接到现有后端 |
| 音质、音效、淡化、一起听 | 待验证，未接入 | 只显示实际可用能力；一起听仅同步控制 |

## 实施顺序

1. 编写协议回归测试并确认缺少实现时失败。
2. 实现本机服务：严格来源、Host、体积限制、一次性配对、顺序命令、停止屏障和会话超时。
3. 实现扩展：显式绑定当前 Apple Music 标签页、轮询、固定适配器、错误提示、断连暂停。
4. 自动验证协议和适配器；打包组件，交用户完成真实网页验收。
5. 验收通过后接入 Mod：统一播放后端、浏览/队列、歌词、多人同步，分别测试后发布测试 JAR。

浏览器适配器不会导出音频，停止/断连不会退出 Apple 账号或关闭标签页。原型依赖 Node.js 22+；最终游戏端计划使用现有 Java 运行时，尚未实现。扩展手动加载一次，更新后在扩展管理页重新加载。

参考：[Chrome 扩展内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[脚本执行](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[Apple MusicKit](https://developer.apple.com/musickit/)。
