# 5.33 会话恢复补充

用户确认关闭的是组件主窗口右上角 ×。已将该操作改为隐藏；退出由父进程/连接失效控制。明确使用既有 Default 非隐私配置并保留同一 UDF，避免通过销毁组件来“关闭登录页”。

原来的 SDK 单标志不足以表示网站和媒体库均可用；新增实际只读库请求验证、缓存和状态分类。不得用磁盘上的布尔值伪造有效授权，不能保证 Apple 过期的登录永不重验。公共目录搜索与热门歌曲不依赖个人媒体库就绪，后者仍需真实权限。

自动检查覆盖空库成功恢复、401 保持未授权、热门歌曲数据规范化、X 隐藏/正式退出策略。真实账号跨游戏重启和 API 读取待实测。

# 5.32 Apple Music 游戏内浏览与登录

## 交互

选择 Apple Music → 点击账号入口 → 自动启动已安装的内嵌组件 → 尝试弹出官方授权窗口。用户完成登录后，只有播放器明确返回 `isAuthorized=true` 才显示已登录、收起窗口并刷新游戏内媒体库。已有有效组件登录资料时可以直接恢复，Apple 要求重新认证时仍需用户本人登录。

不提供未经验证的跨设备二维码登录，不要求用户复制 Apple Cookie/令牌。游戏不读取账号密码；原生组件通过官方网页已有 MusicKit 实例操作，账号凭据保留在组件资料目录。

游戏左侧搜索框显示歌曲结果；左侧列表提供“媒体库歌曲”和个人歌单。点击歌曲、播放全部、上一首/下一首、停止、拖动进度与音量使用现有界面。队列由游戏管理，SDK 每次仅加载当前一首；顺序/随机/单曲循环沿用原有逻辑，切换模式不重启当前歌曲。

## 实现

- 固定操作集：search、songs、playlists、playlistTracks；参数长度、ID 和分页偏移受限，不能请求任意 URL。
- 请求只在现有 Library 后台线程等待，通过匹配命令 ID 的 Future 返回。停止、断连和重配对取消未完成请求；不会在渲染线程等待 Apple 接口。
- 本机只接收过滤后的 ID、歌名、歌手、专辑、封面和时长，最多每页 25 个条目，封面限定 mzstatic HTTPS。响应不包含凭据或原始 API 错误。
- catalog 搜索使用账号 storefront；无法获取地区时明确提示，不强行按美国区搜索。媒体库 ID 与目录播放 ID 保持区分。
- 普通歌曲使用 SDK setQueue；媒体库独有曲目使用 SDK MediaItem 描述，缺少对应能力时提示失败。未匹配的上传歌曲播放需要实测。
- 页边界按原始资源数推进，过滤音乐视频不导致重复页。搜索最多 100 项，媒体库/单歌单最多读取前 500 个资源；暂未提供继续加载按钮。
- 页面加载有代数屏障：先 stop 再到达的 setQueue 完成回调不能启动播放。当前 SDK 歌曲完成事件驱动游戏队列前进，不按估算的人声时长提前换歌。
- 原生组件支持官方登录空白过渡弹窗、完成授权后收起主窗口，并处理授权窗口关闭请求。

## 验证

自动检查：SDK 模拟器验证搜索返回字段过滤、凭据未访问、晚到加载不自动播放；Java RPC 检查响应 ID/元数据过滤/停止取消；打包类检查三种模式、实际队列、保留进度、下一首和停止；无控制台 UTF-8 启动回归及 Gradle/.NET 构建。

待真实账号和 GTNH 实测：官方弹窗触发、授权自动收起、地区搜索、个人媒体库/歌单读取、目录与媒体库独有歌曲完整播放、SDK 结束事件和长时间隐藏运行。

## 尚未实现

Apple 推荐、收藏修改、专辑/歌手独立浏览、歌词/翻译/音译/KTV、音效/无损档位、Apple 多人同步。已有网易云等音源及其一起听继续保留，不通过其音频 URL 链路分享 Apple 音频。

## 安装与验收

同时更新 5.32 JAR 和 `apple-player` 组件，替换旧版文件但保留 accounts 资料。无需 Node、浏览器扩展或手动配对。首次点击账号入口后完成官方登录；若自动授权被站点拒绝，可在组件里点击官方登录按钮。验证：搜索已知歌曲→点击播放→打开媒体库歌单→播放全部→三种模式切换→停止→切换网易云。记录失败步骤和脱敏提示，不发送配对码或 Apple 凭据。

参考：[Apple MusicKit](https://developer.apple.com/musickit/)、[MusicKit 官方示例](https://js-cdn.music.apple.com/musickit/v1/index.html)。当前官方网页实例的兼容性以真实测试为准。
