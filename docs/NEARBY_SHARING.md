# 附近共享与音乐群组

本文对应 `feat/nearby-sharing` 的实现。服务端组件是可选的；客户端不装模组仍然可以正常进入装了模组的服务器。

## 功能

- **附近共享**：主机开启“Share my music”后，同维度、默认 32 格内的已装模组玩家可以听到主机的音乐。超出半径停止；距离越远音量越低。
- **音乐群组**：成员不受距离限制，并支持**同时加入多个群组**。每个成员在“我的群组”里选中一个作为**当前激活群组**，只收听/共享到该群组。房主负责管理，离线不会解散群组；房主主动离开时会把房主转让给下一位成员。任何成员都可以邀请他人（不再限房主）。
- **共享者（speaker）**：任何成员开始播放新曲目、且 `Share to group` 开启并选中了该群组时会自动成为 speaker；多人同时播放时优先正在播放的成员，再取最近开始的那首。speaker 停止/关闭共享/切换群组/离开后自动轮到其他成员，没人共享时回退附近广播。speaker 自己不会收到自己的远端播放。
- **群组页面**：上部是当前群组设置/状态（Hero、房主、成员标签、当前 speaker、`Share to group`、`Hear group`、离开）；下部是“我的群组”、邀请和公开群组列表。按钮带毛玻璃、悬停缩放和弹簧动画。
- **播放优先级**：个人播放 > 群组 > 附近。本地有歌曲时远端流暂停（不卸载），本地停止后恢复；同一时刻只有一路远端，不会与本地重叠。
- **歌词投影**：主机开启“Share my lyrics”后，附近/群组成员可以在主机头顶看到当前歌词行；查看方用“See nearby lyrics”控制。远端会同步主机的字体、平滑/像素风格、颜色、缩放、距离、行数、翻译/音译、发光和逐字摆动（摆动相位按主机帧推进）。如果查看方关闭“See nearby lyrics”，或主机不共享歌词，客户端会用自己的账号/缓存获取歌词，并按自己的单人歌词设置渲染，而不是没有歌词。
- **回退顺序（网易云优先）**：
  1. **L1**：听众用自己的账号解析并下载。
  2. **L2**：听众直接下载主机共享的短期播放 URL。
  3. **L3**：可选的服务端中转。服务端用主机 URL 下载完整文件，再分块发给听众。默认关闭。

## 安装

- 客户端：把 `build/libs/dangomusicgtnh-<version>.jar` 放入 `mods/`。
- 服务端：同一个 JAR 放入服务端 `mods/`，启动后在 `config/dangomusicgtnh/server.cfg` 生成配置。
- 无模组客户端：可以正常进服和游玩；服务端只向完成 Hello 握手的客户端发数据。

## 客户端设置

播放器设置页 → **Multiplayer** 标签：

| 设置 | 默认 | 作用 |
|---|---|---|
| Share my music | 关 | 把当前音乐共享给附近玩家 |
| Hear nearby music | 开 | 播放附近玩家的音乐 |
| Share quality | 192k | 共享 URL 请求的音质（128/192/320k） |
| Share my lyrics | 关 | 共享当前歌词行 |
| See nearby lyrics | 开 | 显示主机头顶的歌词投影；关闭后客户端自行获取并按单人歌词设置渲染 |
| Group takes over | 开 | 加入或收听听歌房时暂停自己的音乐，改放房间里正在放的歌 |
| Resume after group | 开 | 离开或停止收听听歌房后，接着放之前暂停的音乐 |

收听听歌房不再单独给开关：选中（收听）一个房间就是在听。`Share to group`（共享到听歌房，默认开）只在“设置-多人”里保留一份，开着时在房间里放歌就会共享给房间。

附近/群组音乐跟随播放器音量，并额外限制为最高 50%，即使贴着主机也不会超过一半；距离越远衰减越多。关闭 `Nearby` 模块会同时停止分享和收听。

播放栏的停止按钮会关掉 **Hear nearby music**，并**停止收听当前听歌房**（服务端也会记下，下次进服不自动回房）；想继续听时在听歌房页面点 **Listen**。

## 听歌房页面

播放器左侧栏 → **听歌房**（原“音乐群组”）。打开时各块依次淡入。

- 未加入：上部创建听歌房（名称输入框支持中文、Ctrl+A/Ctrl+V），下部列出公开的听歌房，可以直接加入；收到的邀请单独成卡片。**每人最多拥有一个听歌房**，可以加入多个别人的。
- 当前房间：显示房间名、房主、成员标签和当前共享者（DJ）；任何成员都可以邀请在线、已装模组的玩家；**离开**只在这里出现，需要二次确认。
- **我的听歌房**：列出你加入的所有房间（最多 16 个）。当前房间显示 **Current** 和 **停止收听**；其他房间可以点 **Listen** 切换，或点两次 **Leave** 离开。
- 收到邀请：显示邀请人和房间名，可以接受或拒绝；接受后自动选中该房间。新邀请还会弹一条临时提示。
- 自由抢麦：任何成员开始放新歌都会成为 DJ；刚进房的人用的是加入前就在放的歌，不会抢走 DJ，换一首新歌后才会成为 DJ。

听歌房数据保存在服务端 `config/dangomusicgtnh/groups.json`，内容包括成员、房主、最后已知名字和**每人当前所在的房间**。服务器重启、房主离线都不会解散房间；房主主动离开时，房主转给下一位成员。**重进服务器会自动回到上次收听的房间**；如果上次是自己按停止退出收听的，就不自动回。

## 服务端命令

```text
/dangomusic group create <name>
/dangomusic group join <name>
/dangomusic group leave [name]
/dangomusic group info [name]
/dangomusic status
/dangomusic reload          # OP
```

群组持久化到 `config/dangomusicgtnh/groups.json`。房主离线不会解散；房主主动离开会转让给下一位成员。当前共享者（speaker）由正在播放的成员自动产生，不要求是创建人。

## 服务端配置

`config/dangomusicgtnh/server.cfg`：

| 键 | 默认 | 说明 |
|---|---|---|
| enabled | true | 总开关 |
| radiusBlocks | 32 | 附近共享半径 |
| maxHostsPerListener | 4 | 每个听众最多同时收几个 host |
| maxGroupSize | 8 | 群组人数上限 |
| allowLyrics | true | 允许歌词共享 |
| relayEnabled | false | L3 服务端中转总开关 |
| relayMaxListeners | 2 | 同时中转的听众上限 |
| relayMaxMb | 16 | 单曲中转大小上限 |
| relayChunksPerTick | 2 | 每 tick 发送的 4 KiB 块数（20 tick/s） |
| relayAllowLocal | false | 测试用：允许 127.0.0.1 的 URL |

L3 带宽：2 块/tick × 4 KiB × 20 = 160 KiB/s 每路；默认最多 2 路 ≈ 320 KiB/s 服务端上行。调大 `relayChunksPerTick` 会提高速度，也会提高带宽。客户端等待 L3 的超时为 180 秒；默认 16 MiB 上限在 160 KiB/s 下约需 100 秒。

## 网易云权益与 URL

- L1 使用听众自己的账号；没有 VIP 时可能只拿到试听或失败。
- L2 使用主机账号申请的短期 URL。客户端拿不到主机 Cookie/token，只拿到 URL；如果 URL 未绑 IP 且未过期，没有 VIP 的听众也能播完整歌曲。这等于借用主机的 VIP 权益，存在平台 ToS/账号共享风险。
- L3 由服务端下载同一个 URL，再分块给听众；风险更高，默认关闭。
- QQ/酷狗没有专门适配 L3；L1/L2 逻辑已存在，但未实测。

## 已知限制（v1）

- L3 目前只实现“服务端用主机 URL 下载”的 L3a；如果服务端 IP 被平台拒绝，L3b（主机上传音频）尚未实现。
- 完整文件下载后再 seek 播放，起播可能有几秒到几十秒延迟；不是实时流。
- 远端歌词是行级：字体、颜色、发光、行数、翻译/音译和摆动参数已同步，位置使用主机实际渲染锚点，摆动相位按主机帧推进；逐字 KTV 高亮、逐词弹出/文字闪入尚未同步。主机换行拆分与远端单行不同时，摆动随机图案仍可能有差异。
- 服务端可以返回多路附近主机元数据，但客户端一次只播放最近的一路（群组优先）；多路同时混音尚未实现。
- 本地音乐与附近音乐各用一条 Java Sound line，系统混音；没有自动 ducking。
- 服务端对群组/中转操作做了 100 ms 去抖，并限制域名、包大小、行数、人数和 L3 并发；没有持久化审计日志。
- L2 只接受平台 CDN 白名单内的主机 URL，重定向也会逐跳校验；L1 使用听众自己账号解析的地址。
- 分享 URL 每 5 分钟刷新一次；同一首歌循环播放时不会无限复用过期 URL。
- 切换远端歌曲时，旧文件的下载不能被中断，新的下载会排在后面；极端情况下起播会延迟。

## 实测清单

1. 服务端装模组、客户端不装：能正常进服、游玩；服务端无异常。
2. 两个客户端：A 开 Share my music、B 开 Hear nearby；A 在半径内/外移动，B 的播放开始/停止、音量变化；贴脸时音量不超过播放器音量的一半。
3. 优先级：B 本地播放时远端暂停；B 停止本地后远端恢复；B 不本地播放时只听到 A，不会重叠。
4. 歌词：A 开 Share my lyrics、B 开 See nearby lyrics；B 在 A 头顶看到当前行，字体/颜色/位置与 A 的 3D 歌词一致，摆动相位同步（KTV 逐字高亮除外）。再把 B 的 See nearby lyrics 关掉，B 应按自己的单人歌词设置显示自己获取的歌词。
5. 群组：A 在 Music group 页面创建，B 接受邀请或在公开列表加入；A/B 任意一人播放新歌都会成为当前共享者，另一人远离也能听到；两人同时播放时最近开始的一首优先，暂停方不应压过正在播放方；共享者停止/关闭共享后自动切换或回退附近。
6. 灵动岛/播放栏：远端播放时显示来源（本地/附近/群组 + 主机名）；远端模式下上一首/下一首/进度拖动/队列/音质按钮不改变主机。
7. 停止按钮：远端播放时点停止，Hear nearby/Hear group 都变关；重新打开其中一个，音频应能重新接入。
8. 群组输入：点击名称框后占位符消失、光标在空框开头；中文输入法提交后字符不应重复；Ctrl+A/Ctrl+V 可用。
9. 群组 UI：卡片/按钮有毛玻璃、悬停缩放和弹簧动画；阴影不要过重；上部为群组设置，下部为我的群组/邀请/公开群组列表。
10. 多群组：A 创建两个群组，A/B 各自加入；在 **My groups** 点 **Listen** 切换激活群组，只有当前群组播放；底部停止按钮会取消当前群组选中。
11. 持久化/离线：A（房主）离线后群组仍在，其他成员可继续播放/邀请；重启服务端后成员/房主/群组仍在；A 主动离开时房主应转让给下一位成员。
12. 任意成员共享：B 不是创建人，播放新歌后 A 也能听到并把 B 标为当前 speaker；任何成员都能邀请。
13. VIP：A 登录网易云放 VIP 歌；B 不登录网易云；B 的 L1 失败后应走 L2；若 L2 失败，开 L3 再试。
14. 日志：客户端 `logs/fml-client-latest.log`、服务端 `logs/fml-server-latest.log` 中搜索 `DangoMusic`；不应出现 URL/token。
