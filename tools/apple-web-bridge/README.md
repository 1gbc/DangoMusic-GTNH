# Apple Music 官方网页桥接 · 验证组件

这是第一阶段可运行原型，**尚未接入 Mod，也没有新的测试 JAR**。无需 Apple 开发者令牌。用户在官方网页登录，扩展尝试使用网页已经创建的播放器；若站点未暴露兼容实例，会明确报错。没有真实网页测试证据前，不宣称支持完整播放、媒体库或一起听。

## Windows 使用

前提：Node.js 22+，Chrome 或 Edge，以及你本人能在官方网页播放的账号。本组件不改变订阅、DRM 或地区权限。

1. 将整个目录解压到固定位置。
2. 在 Chrome 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启“开发者模式”，点击“加载已解压的扩展程序”，选择本目录内的 **extension** 文件夹。扩展仅请求 Apple Music 网页、本机连接和脚本执行权限。不读取 Cookie。
3. 右键 `start.ps1` → 使用 PowerShell 运行，或在本目录终端运行 `node bridge.cjs`。若系统执行策略阻止脚本，直接用后面的 Node 命令，无需修改执行策略。
4. 控制台会显示一条本机配对链接，**不要发给别人，也不要提交到仓库**。链接 2 分钟内有效，只能使用一次；过期输入 `reconnect` 重新生成。
5. 切到已经能播放歌曲的 `https://music.apple.com/` 标签页，点击 DangoMusic 扩展，将链接粘贴到配对框，点击“配对当前标签页”。安装扩展前已打开的网页请先手动刷新一次，再恢复播放。配对不会验证 Apple 登录，需你在网页完成。
6. 在控制台输入 `status`，核对 `state.title`、`artist`、`positionMs`、`durationMs` 和 `available`。`connected=true` 只表示本机桥接连通，不能证明已登录或完整歌曲可播。

| 命令 | 作用 |
|---|---|
| `status` | 显示脱敏歌曲状态、实际进度、连接状态和待确认命令数 |
| `pause` / `play` | 暂停、继续网页歌曲 |
| `next` / `previous` | 使用网页当前队列切歌 |
| `seek 90` | 跳转到第 90 秒 |
| `volume 0.3` | 网页播放器音量设为 30% |
| `stop` | 请求网页停止，立即清空桥接显示；旧状态不能恢复显示 |
| `reconnect` | 废弃旧会话并生成新链接；在扩展中重新配对 |
| `quit` | 退出本机服务，扩展在心跳超时后尝试暂停网页 |

最好在退出前先执行 `stop`，确认网页停止，再输入 `quit`。扩展弹窗也有“断开连接并暂停”。断开不会退出 Apple 账号，不会关闭浏览器。后台标签页定时器可能被浏览器节流，约 10 秒失联会触发重配对；后台可靠性需真实验证。

## 请按顺序验证

- 播放一首超过两分钟的歌，确认超过试听时长仍可播放，`seek 90` 后可继续出声。
- `status` 进度与网页一致；网页手动暂停、跳转和切歌后，状态也随之变化。
- 依次测试 `pause`、`play`、`next`、`previous`、`volume 0.3`，每次等上一条命令生效。
- 输入 `stop` 后立即 `status`，歌曲状态应为 `null`，网页应停止。若网页没有停，**这算失败**；不能用桥接清空显示代替真正停止。
- 最小化浏览器一分钟，观察连接和进度。刷新网页、关闭标签页、退出服务，再验证重配对。

反馈只需说明浏览器版本、命令、是否生效以及错误文字。不要发送配对链接、Apple Cookie/令牌、密码或网络抓包。

## 自动检查与边界

`node --test check.cjs`：验证真实 HTTP 配对、来源拒绝、字段白名单、停止屏障、旧会话拒绝，并用模拟播放器测试实际时钟读取与固定命令。`node --check` 验证脚本语法。这些检查不能证明 Apple 官方网页的播放器对象可用。

适配器只调用固定播放器方法，不提取音频 URL、不下载受保护音频、不调用私有账号接口。尚无搜索、媒体库、收藏、推荐、歌词、独立队列、游戏 HUD 或多人同步；下一阶段须在真实网页最小闭环成立后再实现。

更新组件时，在扩展管理页点击重新加载，刷新 Apple Music 网页，然后重新配对。
