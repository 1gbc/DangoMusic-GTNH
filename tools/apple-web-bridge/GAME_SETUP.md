# 5.29 游戏内 Apple Music 控制测试

用户已报告独立网页组件测试一切正常。5.29 把这条链路移进 Mod；仍需验证实际 GTNH 界面与播放行为，不能据此认定所有 Apple Music 功能已完成。

## 安装与配对

1. 退出游戏。在旧 Node 验证控制台先输入 `stop`，再输入 `quit`。以后不必运行 `start.ps1`。
2. 把 `dangomusicgtnh-0.1.0-dev.5.29.jar` 放到 GTNH 2.9.0 实例的 `mods`，移除旧版同名 Mod。
3. 浏览器扩展复用上次安装的 `DangoMusic Apple Web Bridge (Probe)`。浏览器保持官方 Apple Music 标签页，使用你自己的账号播放。未安装扩展时，按 README 加载 `extension` 文件夹。
4. 游戏按 M，点击左下角音源切换按钮，选择 **Apple Music**。
5. 点击左下角 Apple Music 账号入口，点击 **复制配对链接**。在官方网页标签页点击扩展图标，粘贴链接并配对。链接两分钟内有效且只能使用一次；过期后点击游戏里的 **重新配对**，重新复制。
6. 回到游戏。网页的当前歌名、歌手、封面和进度应出现于底栏与灵动岛；可关闭连接弹窗继续使用。重新打开弹窗不会主动废弃正在使用的连接。

浏览器需要保持运行。退出账号请在官方网页操作；游戏里的“断开连接”停止桥接，不代表退出 Apple 账号。不要发送配对链接、账号令牌或密码。

## 游戏验收

- 播放超过试听时长，跳到歌曲后段仍能播放；游戏进度与网页一致。
- 使用底栏和组合快捷键测试播放/暂停、上下首、音量；拖动游戏进度条，并核对网页。
- 网页手动切歌、暂停、跳转后游戏正确同步。
- 点击停止后歌曲信息立即清空，灵动岛恢复玩家 ID/FPS/延迟；等待数秒确认未被旧状态恢复。按播放键可继续网页歌曲。
- 切换回网易云，确认 Apple 网页停止，不出现双播；回归原有音源搜索、播放和一起听。
- 断开连接、刷新网页、后台运行一分钟、退出游戏，核对播放与重新配对。网页后台定时器被节流时可能触发十秒会话超时，需要重新配对。

## 本阶段边界

- 当前歌曲和队列来自官方网页。游戏内模式选择与队列按钮在 Apple 播放时禁用；请在官方网页管理歌曲。
- Apple 搜索、媒体库、收藏、推荐、歌词/翻译/音译/KTV、淡入淡出、音效、独立队列和多人同步未接入。不将这些列为已实现功能。
- 不提取音频 URL，不复用网易云 URL 共享路径。原有音源的附近/群组一起听继续保留。
- 断开连接会给扩展约两秒接收停止命令；若浏览器已失联，只能由扩展心跳超时后尝试暂停。游戏退出时同理。不会关闭浏览器标签页。
- 全部状态和配对凭据只存在本机内存，不输出到日志或存档。浏览器负责登录资料和订阅权限校验。

## 自动检查

- `node --test tools/apple-web-bridge/check.cjs`：旧协议与网页适配器回归。
- `GameBridgeCheck.java`：Java HTTP 配对、会话隔离、字段过滤、停止屏障。
- `GameStateCheck.java`：使用实际打包类检查游戏状态、真实进度、暂停跳转、停止后的空闲状态和音源隔离。
- `gradle build --offline`：编译打包，Java 类目标为 8。

Java 检查使用 JDK 25 源文件启动，classpath 包含构建产物与 Gson 2.2.4。它们不替代真实 GTNH 2.9.0 实测。
